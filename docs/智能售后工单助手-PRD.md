## 1. 执行摘要

本产品是一套 **AI 优先的多租户 SaaS 售后工单系统**，服务两类客户：**连锁企业总部**（餐饮/零售/便利/药房等 50~2000 家门店的软硬件维护报修）与**品牌厂商**（需要跨区域上门安装维修的产品品牌）。

与传统售后 SaaS"表单 + 流程 + 报表"的形态相反，本产品的入口是**豆包式 AI 对话**：用户（店员/消费者）先问，AI 基于企业知识库（自建知识库 + 飞书知识库 + 历史工单沉淀）回答，联网搜索兜底；拦不住的问题由 AI 预填表单、用户确认后一键转工单；调度员（后期由 agent）分派给服务资源池中的工程师；工程师通过微信小程序/飞书（钉钉）完成接单、上门签到、处理反馈、结单；结单内容经质量门沉淀回知识库。**由此形成飞轮：用得越久，知识库越厚，拦截率越高，人工工单越少，客户成本越低。**

P0 交付标准闭环：用户端对话 + RAG 问答 + AI 填单；管理端工单池 + 手动派单 + 资源池 + 台账 + 简版看板；工程师端小程序（完整操作）+ 一个生态端（飞书或钉钉，轻操作）；底座（多租户、租户档案、三级权限、LLM 网关计量、通知总线 + 降级链）。

## 2. 问题与方案

### 2.1 现状痛点

| 角色 | 现状 | 痛点 |
|---|---|---|
| 门店店员/店长 | 设备坏了打电话、发微信找总部 IT 或本地服务商 | 找不到人、无进度、同一问题反复问 |
| C 端消费者 | 打品牌 400 电话排队、公众号留言无人回 | 慢、描述不清、反复沟通 |
| 总部领导/品牌售后负责人 | 报修散落在电话/微信/Excel，无统一数据 | 看不到工单量、响应时效、服务商质量，无法考核 |
| 调度员 | 微信群里人工派单 | 凭记忆派单、漏单、无负载视图 |
| 工程师/服务商 | 被动等电话/群消息 | 信息不全（地址/设备/故障）、跑空趟 |

### 2.2 方案概述

一句话定位：**"连锁企业的 AI 售后台：店员问一句就能解决，解决不了的自动变工单、自动派到人。"**

四条产品红线（"轻量"的边界）：
1. **开通即用**：企业 1 天内完成开通和知识库对接，无实施驻场
2. **不做重流程引擎**：几套固定工单状态机模板 + 轻配置，不做 BPM
3. **不做 ERP 级结算**：P0 只做服务费记录与对账单导出，不做复杂分成
4. **移动优先**：管理端 Web；用户端 H5（租户品牌化）；工程师端小程序 + 生态应用

### 2.3 商业影响

- 差异化：AI-native（对话拦截、AI 填单、知识自动沉淀），竞品（售后宝、瑞云服务云、易维帮助台）均为表单优先、AI 后贴
- ROI 叙事：拦截率直接换算为客户省下的人工工单成本；拦截率 + 单工单成本下降曲线是续费故事
- 商业模式（P0 阶段建议）：连锁型按 **网点数订阅 + AI 用量**；品牌型按 **工单量/工程师数订阅 + AI 用量** ⚠️ 待确认

## 3. 成功指标

**北极星指标：AI 拦截率** = 对话解决问题且未生成工单的会话数 / 总服务会话数。

| 指标 | P0 试点目标 | 备注 |
|---|---|---|
| AI 拦截率（连锁型租户） | ≥ 40% ⚠️ | 上线 3 个月内 |
| AI 拦截率（品牌型租户） | ≥ 25% ⚠️ | C 端容错低，门槛更保守 |
| AI 首响时间 | < 5 秒 | 对话首 token |
| AI 填单后用户确认耗时 | < 60 秒 | 中位数 |
| 工单人工分派首响 | < 30 分钟 | 调度员工作时间内 ⚠️ |
| 通知降级链内送达率 | ≥ 99% | 以通知记录为准 |
| 结单知识草稿生成率 | 100% | P0 生成存档，P1 上人审入库 |

## 4. 用户画像

### P1 门店用户（店员/店长）——连锁型租户
- **角色**：报修发起人，设备使用者
- **目标**：设备尽快恢复、问题有人跟进、操作问题当场解决
- **痛点**：不知道找谁、同一问题反复问、进度黑盒
- **技术水位**：低，微信重度用户，不装新 App

### P2 C 端消费者——品牌型租户
- **角色**：产品购买者，报修/报装发起人
- **目标**：快速预约上门、了解进度
- **痛点**：电话排队、描述不清故障
- **技术水位**：低-中；**对 AI 答错容忍度低**，需更严置信度阈值与免责话术

### P3 调度员（租户内部或服务商）
- **角色**：工单分派与跟踪的核心操作者
- **目标**：不漏单、派得准、时效达标
- **痛点**：多渠道收单、无负载视图、催办靠人肉

### P4 管理者（总部领导/品牌售后负责人）
- **角色**：数据查看与决策
- **目标**：看见成本、时效、服务质量趋势
- **痛点**：无数据、无法考核服务商

### P5 工程师（内部 IT / 外部服务商工程师）
- **角色**：接单与上门执行
- **目标**：信息全（地址/设备/故障图）、不被骚扰、结单快
- **痛点**：电话派单信息缺失、微信消息淹没、跨企业要装多个 App

## 5. 租户档案（双客群一个内核）

| 维度 | 连锁型租户 | 品牌型租户 |
|---|---|---|
| 租户内用户 | 店员/店长（组织架构身份，管理员导入） | C 端消费者（手机号验证码/微信授权轻身份） |
| 用户端入口 | 企微/飞书工作台内嵌 H5、独立 H5（短信/二维码触达） | 微信内 H5、公众号菜单、后续微信客服 |
| 用户端品牌化 | 租户 LOGO + "XX 售后助手" | 同左 |
| 服务资源池默认构成 | 外部本地服务商为主 + 内部 IT | 自有/授权工程师为主 + 服务商 |
| AI 置信度门槛（低置信转建单） | 常规 | 更严格 ⚠️ 具体阈值联调期定 |
| 免责话术 | 内部提示即可 | 必须开启（面向消费者的合规提示） |
| 知识库典型来源 | 设备操作手册、错误码表、开业流程、历史工单 | 产品说明书、FAQ、安装规范、历史工单 |
| 结算 | P0 不做 | P1 提前（服务商对账单） |
| 服务对象模型 | 网点（含设备台账） | 消费者客户 + 收货/安装地址 |

同一内核：会话/RAG/工单/状态机/调度/通知总线，档案只切换默认配置与开关。

## 6. 核心用户故事与验收标准

### 用户端

**US-1 会话问答**
As 门店用户，我想直接打字或发照片提问，以便不用等人就能解决操作类问题。
- [ ] 支持新建会话与在历史会话中追问，会话标题由 AI 自动生成
- [ ] 回答必须附来源（知识库文档名 / 历史工单号），无来源时明确标注"联网参考"或"未能找到依据"
- [ ] 知识库检索优先，命中不足时自动联网搜索，触发前完成企业信息脱敏
- [ ] 每轮对话界面常驻"转人工 / 直接报修"逃生入口

**US-2 AI 填单转工单**
As 门店用户，我想让 AI 把对话内容自动变成工单，以便不用重复填写。
- [ ] 会话中一键"生成工单"，AI 预填：网点、设备、故障现象、错误码、已尝试步骤、期望时间、图片
- [ ] 用户可修改每个字段后确认提交；提交后可在会话中看到工单卡片与状态
- [ ] 连锁型：网点与设备按用户身份默认带出，可改；品牌型：地址与联系方式必填校验

**US-3 手动新建（AI 辅助）**
As 任意用户，我想直接打开表单报修，以便跳过对话。
- [ ] 表单字段 AI 主动预填（基于用户身份、历史会话、剪贴板描述粘贴的语义解析）
- [ ] 必填校验：故障描述 ≥ 10 字或含 1 张图片；品牌型增加联系电话与地址

**US-4 工单跟踪**
As 用户，我想看到工单进度并在完成后确认，以便心里有数。
- [ ] 工单列表 + 详情（状态、工程师姓名/电话脱敏展示、时间线）
- [ ] 状态变更推送（按第 10 节通知矩阵）；"待确认"状态下用户可确认完成或驳回（驳回必填原因）

### 管理端

**US-5 手动分派**
As 调度员，我想在一个派单台看到所有待分派工单和工程师负载，以便快速派准。
- [ ] 工单池支持按状态/优先级/类型/网点/超时筛选与关键词搜索
- [ ] 工程师列表展示：状态（空闲/忙碌）、当前在办数、服务区域、技能标签
- [ ] 一键分派 / 改派（改派需填原因，记入时间线）；分派即触发通知
- [ ] 代客建单：调度员可手工录入电话/微信渠道来的报修

**US-6 通知兜底**
As 调度员，我想看到通知失败的工单，以便人工补位不漏单。
- [ ] 工作台常驻"通知失败/未送达"队列，展示降级链终点与最后尝试时间
- [ ] 队列内可直接操作：重发、电话联系（展示号码）、改派

**US-7 管理看板**
As 管理者，我想看到拦截率与工单时效趋势，以便评估投入产出。
- [ ] P0 简版看板：拦截率趋势、工单量趋势、平均首响/解决时长、网点工单 TOP、服务商质量排名（按完成量/驳回率/时长）
- [ ] 支持按时间范围筛选；数据每日汇总，T+1 更新（P0 不做实时）

**US-8 知识库管理**
As 租户管理员，我想把飞书知识库接进来并管控 AI 行为，以便快速冷启动。
- [ ] 飞书知识库对接：选择知识空间/目录，增量同步，展示同步状态与失败原因
- [ ] 自建知识库：在线新建/编辑文档、批量上传（Word/PDF/Markdown/图片 OCR 留 P1）
- [ ] 开关：联网搜索（默认开）、免责话术（品牌型强制开）、置信度阈值（低置信时 AI 主动建议转工单）

### 工程师端

**US-9 接单**
As 工程师，我想实时收到新工单通知并一键接单，以便不漏活。
- [ ] 通知降级链送达（第 10 节）；小程序内可接单/拒单（拒单必填原因）
- [ ] 首次使用零注册：手机号验证码即登录，首次接单自动入资源池（需调度员审核确认信息）
- [ ] 生态端（飞书/钉钉）消息卡片支持接单、改状态、查工单（轻操作）

**US-10 上门执行与结单**
As 工程师，我想在手机上完成整个服务过程记录，以便不用回办公室补单。
- [ ] 工单详情含：地址导航、设备信息、故障图、对话摘要（AI 生成）
- [ ] 上门签到（定位打卡，与网点/客户地址偏差 > 500 米时记录标记）；处理过程记录（文字+照片）
- [ ] 结单提交：处理摘要（AI 辅助生成草稿）、配件使用记录（P0 仅记录）、现场照片
- [ ] 工单详情页自动展示"相似案例"：知识库与历史工单的相似维修方案（复用 RAG）

## 7. 功能需求详述（按模块）

### 7.1 底座平台

**多租户与权限**
- 租户隔离：数据层强制租户隔离（行级或库级），跨租户访问在服务端阻断
- 权限三级：租户 → 组织（连锁=网点/区域，品牌=区域）→ 角色
- P0 角色：租户管理员、管理者（只读+看板）、调度员、知识库管理员、内部工程师、服务商成员（仅本服务商工单）、普通用户
- 服务商（外部企业）作为租户下的资源主体，其成员只能看到分派给本服务商的工单

**LLM 网关**
- 统一网关对接 2 家模型供应商（主备），按租户计量 token 与调用次数
- 统一能力：对话/RAG/填单/摘要/相似案例，全部走网关，便于计量与切换模型
- 联网搜索前置脱敏过滤器：网点名、资产编号、手机号、单据号在出网请求中替换为占位符

**知识库引擎（RAG）**
- 向量检索 + 关键词混合检索；来源类型：自建文档、飞书文档、历史工单（结构化+处理摘要）
- 引用追溯：每个回答片段可回溯到源文档段落或工单号
- 质量门：结单后 AI 判断沉淀价值 → 高置信自动入库（品牌型默认全部转人审）→ 中置信生成草稿入待审队列（P0 仅生成与存档，审核界面 P1 上线前由管理员在后台简单列表处理）

**通知总线（核心基础设施）**
- 统一接口：业务事件 → 总线 → 通道适配器（小程序订阅消息/服务号模板/短信/飞书或钉钉应用消息/电话外呼 P1）
- 降级链（按事件配置，默认）：小程序订阅消息 → 服务号模板 → 短信 →（SLA 升级时）电话外呼
- 全量送达留痕：每条通知记录通道、时间、送达状态；失败进入调度员兜底队列
- 订阅消息额度管理：工程师端关键操作前引导一次性订阅授权，额度池监控告警

### 7.2 用户端（H5，租户品牌化，豆包式布局）

页面清单：
1. **会话列表页**（左栏，桌面端；移动端为首页列表）：新会话入口、历史会话（AI 生成标题、含工单标记角标）
2. **对话页**：消息流（Markdown + 图片 + 引用来源可点开）、常驻逃生入口（转人工/直接报修）、AI 填单确认卡片（字段可编辑）、图片上传（P0 仅转述+存储，识别 P1）
3. **工单卡片/详情页**：状态步骤条、时间线、工程师信息（脱敏）、确认/驳回操作
4. **新建工单页**：AI 预填表单、图片上传、提交
5. **我的工单列表**：进行中/已完成分组

登录：连锁型=组织身份（管理员导入手机号，验证码登录即绑定）；品牌型=手机号验证码/微信授权，首次登录创建轻量客户档案。

### 7.3 管理端（Web）

页面清单：
1. **工作台**：今日待分派、超时预警、通知失败队列、今日趋势
2. **工单管理**：全部工单（筛选/搜索/导出 CSV）、工单详情（完整时间线、对话原文入口、分派/改派/关单/备注）、代客建单
3. **派单台**：待分派池 + 工程师负载列表（地图视图 P1）
4. **资源池**：工程师管理（信息、技能标签、服务区域、启停用）、服务商管理（企业信息、成员、服务区域、质量记录）
5. **台账**（连锁型重点）：网点管理（批量导入 Excel）、设备管理（网点挂靠、资产编号、保修期）
6. **知识库管理**：文档列表、飞书同步任务、待审知识草稿（简版）、AI 开关配置
7. **数据看板**（US-7）
8. **系统设置**：租户信息与品牌化（LOGO/名称）、通知模板、角色权限、租户档案切换项、渠道接入配置

### 7.4 工程师端

**微信小程序（完整操作）**页面清单：
1. 工单列表（待接单/进行中/已完成）
2. 工单详情（信息 + 导航 + 相似案例推荐）
3. 接单/拒单（拒单原因）
4. 上门签到（定位打卡）
5. 处理记录（文字+照片，可多次追加）
6. 结单提交（AI 摘要草稿可编辑、配件记录、照片）
7. 我的（个人信息、服务区域与技能标签维护）

**生态端（飞书或钉钉其一，P0 按首发客户主生态确定 ⚠️）**：
- 应用消息卡片：新工单通知（含关键信息）、接单、更新状态、查看工单（跳转 H5 详情）
- 定位为"通知可靠送达 + 轻操作"，完整操作引导至小程序

## 8. 工单状态机（P0）

```
[草稿] --用户确认提交--> [待分派]
[待分派] --调度员分派--> [待接单]
[待接单] --工程师接单--> [已接单]
[待接单] --工程师拒单(填原因)--> [待分派]（拒单记录入时间线）
[待接单/已接单] --调度员改派--> [待分派]
[已接单] --工程师上门签到--> [处理中]
[处理中] --等配件/等客户(填原因)--> [挂起] --恢复--> [处理中]
[处理中] --工程师提交结单--> [待确认]
[待确认] --用户确认--> [已完成]
[待确认] --用户驳回(填原因)--> [处理中]
[已完成] --7天无异议自动/调度员手动--> [已关闭]
[任意未完成态] --用户取消/调度员关单(填原因)--> [已取消]
```

- 优先级：紧急（停业/安全风险）/ 高（影响经营）/ 中（局部影响）/ 低（咨询优化）；创建时 AI 建议优先级，调度员可改
- SLA 字段 P0 预留（响应时限/解决时限），SLA 引擎与升级动作 P1

## 9. 工单核心字段

> **修订注记（v1.1）**：本表按《工单模型与触发引擎设计.md》三层架构理解——工单号/租户/状态/优先级/来源/服务对象/时间戳组为 **L1 固化系统字段**；设备信息/故障描述/结单摘要等为 **L2 语义槽位**（AI 从自由描述提炼，带置信度，租户可扩展槽位）；其余为 L3 自由叙事。无固定录入表单，交互形态为 AI 提炼确认卡。

| 字段 | 说明 | 必填 |
|---|---|---|
| 工单号 | 租户内唯一，规则：租户前缀+日期+流水 | 系统 |
| 租户/档案类型 | 连锁型/品牌型 | 系统 |
| 类型 | 报修/安装/巡检/其他 | 是（AI 建议） |
| 来源 | 会话生成/手动新建/调度员代建 | 系统 |
| 优先级 | 紧急/高/中/低 | 是（AI 建议） |
| 服务对象 | 连锁型=网点；品牌型=客户+地址 | 是 |
| 设备信息 | 名称/型号/资产编号/照片 | 报修类必填 |
| 故障描述 | 文本+图片 | 是 |
| 期望上门时间 | 时间窗 | 否 |
| 分派对象 | 工程师/服务商 | 分派时 |
| 状态 | 第 8 节 | 系统 |

## 11. 非功能需求

**性能**（⚠️ 待确认基线）：
- 对话首 token < 3 秒（P95）；管理端 API P95 < 500ms；小程序冷启动 < 3 秒
- P0 容量：单租户 500 会话/日、平台 10 万工单/月、并发 500

**安全与合规**：
- 租户数据强制隔离；手机号等 PII 加密存储、界面脱敏展示
- 联网搜索出网脱敏（架构层强制，非提示词约束）
- 日志脱敏；操作审计（管理端全量操作留痕）
- 参考《个人信息保护法》与等保二级要求；微信生态与飞书开放平台规范

**可用性**：
- 服务可用性目标 99.5%（P0）；LLM 主备双供应商，主故障 5 分钟内切备
- 通知总线为最高可用性等级组件（独立部署、失败可重放）

**兼容性**：管理端 Chrome/Edge/Safari 现代版本；用户端 H5 主流移动浏览器 + 微信内置浏览器；小程序基础库 2.x+。

## 12. 明确不做（P0 Out of Scope）

- Agent 市场与第三方 agent 接入（P2）；自动派单 agent（P1）
- SLA 引擎与自动升级（P1）；结算与分成（P1 品牌型对账单）
- 第二个生态端（钉钉或飞书，P1）
- 图片智能识别（错误码/铭牌，P1）；语音输入（P1）
- 地图调度视图（P1）；知识库 OCR（P1）
- 微信客服/公众号深度接入（P1）；独立 App；多语言；ERP/CRM 对接
- 租户级模型微调（P2，路线：共享基座 + 租户 RAG + 问答对沉淀 + 后期 LoRA）

## 16. 附录：术语表

- **拦截率（Deflection Rate）**：对话解决问题且未生成工单的会话占比，北极星指标
- **租户档案**：连锁型/品牌型两种租户配置模板，共用同一产品内核
- **资源池**：内部工程师、签约服务商、平台接单工程师的统一抽象，调度引擎只面向资源池
- **通知降级链**：小程序订阅消息 → 服务号模板 → 短信 →（升级时）电话外呼的递补送达机制
- **逃生门**：用户端常驻的"转人工/直接报修"入口，保证不被 AI 硬聊拦截
- **质量门**：工单知识沉淀的置信度分级机制（自动入库 / 草稿人审 / 不沉淀）
- **SLA**：响应与解决时限承诺，P0 仅预留字段
- **ISV 应用**：以服务商身份上架到飞书/钉钉的应用形态，可服务多个客户租户
