## 1. 定位与设计原则

AI 工作台是**租户运营的统一指挥中心**，管理端默认首屏。它把四类"流"放进同一个界面：

| 流 | 内容 | 发起方 |
|---|---|---|
| Agent 协同流 | agent 的建议、预警、留痕 | Agent |
| 人工会话流 | 用户端"转人工"接入的对话 | 用户 |
| AI 问询流 | 管理者/调度员向 AI 提问 | 管理端用户 |
| 工单操作流 | 分派/改派/催办/建单等操作 | 管理端用户 + Agent |

三条设计原则：
1. **卡片是原子操作**——agent 的每个建议都是可执行卡片，处理 = 一次点击，全程留痕
2. **对话是万能入口**——问数据、下指令都在输入框，AI 生成确认卡，人确认后执行（ChatOps）
3. **右栏随上下文**——中栏在干什么，右栏就显示什么的支撑信息，不用切换页面

角色差异（同一界面，权限不同）：
- **调度员**：全部可操作（人工会话、协同卡、工单指令）
- **管理者**：AI 问询 + 看板 + 协同卡审批类可操作，人工会话不分配（除非兼任）
- **知识管理员**：知识沉淀频道的审核操作

## 2. 左栏：四个区域的生命周期与排序规则

### 2.1 人工服务台（生命周期收敛）

| 规则 | 说明 |
|---|---|
| 显示范围 | 仅**排队中**与**服务中**的会话 |
| 排序 | 排队中（按等待时长倒序，超 2 分钟整行黄色高亮）> 服务中（按接入时间正序） |
| 每项信息 | 用户名 · 网点、等待倒计时、来源（转人工）、情绪/紧急标签（AI 判定）、红点（有未读新消息） |
| 退出规则 | 会话结束 → 立即离开左栏 → 24h 后自动归档（历史抽屉可见） |
| 空态 | 单行提示"暂无排队 · AI 接待中 + 今日接入 N"，新会话进来立即替换 |
| 徽标 | 分组标题右侧显示排队数；有会话时隐藏 |
| 整组收起 | 标题行点击 ▾/▸，状态记忆到 localStorage（按用户） |

排队通知链：用户点转人工 → 通知总线（生态应用消息加急 → 短信，若 3 分钟无人接入）→ 升级通知当班负责人。

### 2.2 Agent 频道（结构固定）

| 规则 | 说明 |
|---|---|
| 固定入口 | **工单工作台**（永远第一位，蓝色状态点），聚合全部待处理工单操作 |
| 频道列表 | 运行中的 agent（绿点/黄点=有预警）+ 待处理数角标 + P2 占位（灰色：质检巡检、结算核对） |
| 排序 | 工单工作台 → 按 agent 上线时间；租户管理员可在设置中调整 |
| 点击语义 | 进入**频道视图**（不是打开一个会话）；频道是常驻实体，不随会话增减 |
| 频道副标题 | 职能 + 今日待处理（如"分派 / 改派 · 待确认 1"） |

### 2.3 AI 会话（窗口收敛）

| 规则 | 说明 |
|---|---|
| 显示范围 | 默认最近 **10 条**，按"最后活跃时间"倒序（活跃 = 产生任何新消息，含 AI 回复完成） |
| 沉降规则 | 第 11 条自动沉入展开区；新会话或老会话来新消息会浮回窗口内 |
| 展开/收起 | 标题右侧"展开"按钮，展开显示全部未归档会话，按钮变"收起" |
| 归档规则（**待确认 Q1**） | 建议：**30 天未活跃**自动转归档（进历史抽屉，保留 90 天）；AI 会话不设"结束"概念 |
| 置顶（P1） | 手动置顶的会话固定在窗口顶部，不占 10 条名额 |
| 与人工会话的关系 | 同一用户的事件可能同时产生 AI 会话与人工会话，两者独立记录，工单详情页双向关联 |

### 2.4 底部：全部会话历史（抽屉）

- 范围：全量未归档 + 已归档（人工 24h 后归档、AI 30 天未活跃归档，均保留 90 天）
- 能力：搜索（标题/对象/网点/关键词）、类型筛选（全部/人工接入/AI 会话/归档）、按天分组
- 点击行为：未归档 → 打开对应视图（人工→S2，AI→S1 并定位）；已归档 → 只读回放
- 底部规则说明常显（归档规则透明化）

## 3. 中栏：四种视图模式（状态机）

```
                 ┌─ 左栏点排队会话 ──→ S2 人工会话 ─┐
S1 指挥中心（默认）┼─ 左栏点 Agent 频道 → S3 频道视图 ─┼─ 返回按钮 → S1
                 └─ 左栏点工单工作台 → S4 工单台 ──┘
```

| 视图 | 内容 | 输入框模式 | 右栏 |
|---|---|---|---|
| S1 指挥中心 | 完整时间流（四类消息混排）+ 筛选 tabs | **问询模式** | 态势面板 |
| S2 人工会话 | 单会话：AI 上下文摘要卡 + 消息流 + 服务操作 | **服务模式**（人工回复 + AI 建议回复 chips） | 服务对象资料 |
| S3 频道视图 | 该频道的协同卡流（含留痕） | **指令模式**（该频道） | Agent 运行详情 |
| S4 工单工作台 | 全部待处理操作卡 + 执行留痕 | **指令模式**（跨频道） | 工单待办汇总 |

规则：
- 视图切换**不丢状态**：S1 的筛选、滚动位置按会话记忆；返回 S1 时恢复
- S2/S3/S4 顶部均有返回按钮；左栏高亮跟随当前视图
- 输入框三模式的 placeholder、chips、发送行为随之切换；**草稿按模式分别保存**
- 筛选 tabs（全部/待我处理/Agent 动态/AI 会话）只在 S1 有效：
  - 待我处理 = 所有 todo 状态协同卡（含跨频道）
  - 计数徽标与左栏角标、右栏待处理三处实时联动（同一数据源）

## 4. 消息流元素体系（S1/S3/S4 共用语法）

### 4.1 系统分隔条
日期 / 阶段（"Agent 早报""你的问询"），跨 30 分钟无消息自动插入时间分隔。

### 4.2 Agent 协同卡（核心组件）

**结构**：头部（Agent 身份头像 + 名称 + 时间 + 状态 chip）→ 正文（事项一句话）→ 依据区（数据依据 + 置信度 + 引用来源）→ 操作区

**状态机**：
```
待处理(todo) ──批准/通过──→ 已执行(resolved)
     ├────调整──→ 跳转对应操作台（派单台/知识库）
     ├────忽略──→ 已忽略（半透明留痕）
     └────超时──→ 已过期（自动生成升级卡，仅 SLA 类）
```

**操作按钮三分法**：批准类（主按钮，直接执行）、调整类（跳转对应完整操作台）、忽略类（次按钮，需记录原因或二次点击确认）。

**联动规则**：卡片状态变化 → 左栏频道角标 ±1 → 右栏待处理 ±1 → tabs 计数 ±1（同一事件源驱动，见 §7）。

**留痕要求**：已执行卡不可删除，显示执行人 + 耗时（如"4 秒完成，人工派单平均 6 分钟"），agent 据此记录正/负反馈用于策略调优。

### 4.3 人机问询消息

- 用户问题气泡（右侧，品牌蓝浅底）
- AI 回答：**来源标签**（实时数据 / 知识库 / 联网脱敏）+ 正文 + 富卡片段（迷你 KPI 格、计划清单、排名）+ **引用块**（可点开源文档/工单/报表）+ 追问 chips
- 回答边界：AI 只引用租户内数据；查不到就明说，不编造

### 4.4 指令确认卡（ChatOps，本次设计核心）

**流程**：
```
用户输入指令 → AI 解析（意图+实体：工单号/工程师/时间）→ 生成确认卡 → [确认执行] / [取消] → 执行 + 留痕
```

**规则**：
- 解析失败或歧义 → AI 追问澄清（"是 GD-0010 天府三街店的监控单吗？"），**绝不猜**
- 确认卡必须包含：操作内容（单号、对象、动作）+ 依据（为什么推荐这个人/这个时间）+ 置信度
- 危险操作（关单、批量操作、改优先级到紧急）→ 强制确认 + 权限校验
- 执行后自动触发通知总线的对应事件（分派→通知工程师等）
- 每条指令与执行记录沉淀到对应 agent 频道（形成操作日志流）

**P0 指令范围**：分派、改派、催办、建单、改约、查询（演示为固定剧本）；**P1** 完整 NLU + 多工单批量（"把今天所有低优先级派给空闲的人"）。

### 4.5 AI 摘要卡（长流折叠）

会话消息 > 50 条时：默认只加载最近 50 条 + 顶部"查看更早"按钮 + 更早内容自动生成 AI 摘要卡（时间段 + 归纳事项）；向上滚动按 50 条增量加载。

## 5. 右栏：上下文面板（四态）

| 态 | 触发 | 内容 | 刷新 |
|---|---|---|---|
| 态势面板 | S1 | 今日指标（拦截率/待分派/进行中/首响）、待我处理、通知兜底队列、Agent 运行态 | 指标实时；看板 T+1 标注 |
| 服务对象 | S2 | 用户卡（姓名/角色/年限/VIP/脱敏电话）、近 90 天工单、本单相关设备、AI 建议 + 一键建单 | 接入时拉取，静态 |
| Agent 详情 | S3 | 状态统计、今日执行留痕、决策策略（权重/阈值，只读）、人工参与模式、调整策略入口（P1） | 实时 |
| 工单待办 | S4 | 待办汇总（待分派/超时/待确认/完成）、待处理列表（点击跳派单台）、指令引导 | 实时 |

规则：右栏宽度固定 288px；窄屏（<1280px）折叠为图标条（P1）；模块不可自定义（**待确认 Q5**）。

## 6. 关键端到端流程

### 6.1 转人工全链路
用户点逃生门 → AI 交接说明（附排查记录）→ 排队（左栏黄条 + 倒计时 + 通知总线提醒当班调度）→ 调度接入（AI 上下文摘要卡自动置顶：原因/已试步骤/情绪/建议）→ 服务（AI 建议回复 chips + 引用知识库 + 插入工单卡 + 一键建单）→ 结束（转回 AI + 满意度评价 + 24h 归档）。

**并发规则（待确认 Q2）**：一人工会话同时只允许一人服务（接入即锁定，其他人只读）；调度员离线 5 分钟自动释放回排队并通知。

### 6.2 指令操作全链路
见 §4.4。执行动作的完整留痕进入对应 agent 频道，构成"人也在教 agent"的数据资产。

### 6.3 Agent 协同全链路
agent 触发条件（如新工单进入待分派池超 5 分钟）→ 生成建议卡（含依据与置信度）→ 人处理 → agent 记录反馈（采纳/调整/驳回原因）→ 月度策略调优报告（P2）。

## 7. 数据模型支撑（核心对象）

| 对象 | 关键字段 | 说明 |
|---|---|---|
| Conversation（会话） | id、type（ai/human/channel）、participants、status、lastActiveAt、archivedAt | 三类统一模型，左栏与抽屉同源 |
| AgentCard（协同卡） | id、agentKey、type、status（todo/resolved/ignored/expired）、evidence、confidence、expiresAt、relatedTicket | 状态机驱动三处计数联动 |
| CommandRecord（指令） | id、text、parsedIntent、confirmCardId、executor、result | ChatOps 留痕 |
| 通知事件 | 事件类型 ↔ 通道矩阵（PRD §10） | 所有执行动作复用通知总线 |

**联动实现要点**：左栏角标、右栏待处理、tabs 计数由同一"未处理 AgentCard 计数"查询驱动，前端订阅变更事件刷新，避免三处不一致。

## 8. 边界与异常

| 场景 | 处理 |
|---|---|
| 多调度并发处理同一协同卡 | 乐观锁：后操作者收到"已被 XX 处理"提示，卡片状态以先者为准 |
| 调度员全部离线时有转人工 | 排队超 3 分钟 → 电话外呼当班负责人（通知降级链） |
| LLM 故障 | 问询模式与指令模式禁用并提示；协同卡、人工会话、普通操作不受影响（它们不依赖实时 LLM） |
| Agent 故障 | 频道状态点变灰 + 右栏提示"上次心跳"；其待处理卡保留，不自动过期（除 SLA 类） |
| 断线重连 | 消息流按 sequence 增量拉取；重连后红点补提示 |
| 会话数据隔离 | 服务对象资料仅本租户；跨网点数据按角色权限过滤（区域调度只见本区域） |

## 10. 待确认问题（评审讨论点）

| # | 问题 | 当前假设 |
|---|---|---|
| Q1 | AI 会话归档阈值：30 天未活跃自动归档是否合适？ | 30 天 + 保留 90 天 |
| Q2 | 人工会话并发策略：抢单制（先点先得）还是指派制（按负载自动分配）？ | P0 抢单制，P1 评估自动分配 |
| Q3 | 指令模式权限：管理者能否执行分派类指令，还是仅调度员？ | 分派/改派仅调度员；查询/建单开放管理者 |
| Q4 | 协同卡默认过期时间：SLA 类跟随 SLA 时限，建议类 4 小时是否合适？ | 4h，过期不消失只降级显示 |

| Q6 | AI 辅助回复（人工会话内的草拟）默认开启还是按租户开关？ | 连锁型默认开、品牌型默认开但话术更保守 |
| Q7 | 指令的审计要求：是否需要二次确认以外的审批流（如金额相关）？ | P0 无审批流，关单/紧急优先级需二次确认 |
