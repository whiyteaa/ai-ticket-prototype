# 工单模型与触发引擎设计（AI 原生工单）

**版本**：v1.0
**日期**：2026-10-08
**状态**：待评审
**定位**：本文件是整套设计的"里子"——定义工单的数据模型、触发引擎与 Agent 分级，是《详细功能设计说明书》的上层依据；PRD §9（工单字段）与 AI 工作台协同卡机制按本文件修订。

**核心命题**：摆脱传统工单平台"字段驱动流程"的固化逻辑，改为**语义驱动流程、结构后置生成**——用户自由描述，AI 提炼结构，结构服务于流程而非录入。

---

## 1. AI 原生工单模型：三层字段架构

**原则：用户不填表 ≠ 系统没有结构。结构从"录入时约束"后置为"理解后提炼"。**

```
用户自由描述（文本/图片/对话）
        │ LLM 提炼（一次推理同时完成填单与分类）
        ▼
┌─ L1 系统字段（固化）── 流程语言：状态机/SLA/路由/权限的锚点
├─ L2 语义槽位（提炼）── 业务语义：触发器与调度的锚点
└─ L3 自由叙事（整理）── 人读的：完整上下文，不参与逻辑
```

### 1.1 L1 系统字段（固化，全租户一致）

| 字段 | 说明 | 谁写入 |
|---|---|---|
| 工单号 | 租户前缀+日期+流水 | 系统 |
| 状态 | 状态机（PRD §8） | 系统 |
| 优先级 | 紧急/高/中/低 | AI 建议 → 人可改（见 §3.3） |
| 服务对象 | 网点/客户 + 地址 | 身份带出/AI 抽取 → 确认卡校对 |
| 来源 | 会话生成/手动/代建/agent | 系统 |
| 时间戳组 | 创建/分派/接单/签到/结单/完成 | 系统 |

**不可模糊的理由**：状态机流转、SLA 计时起点、通知路由（找谁）、权限过滤（谁可见）全部依赖 L1；这是流程语言，模糊即失控。

### 1.2 L2 语义槽位（AI 提炼，带置信度）

**槽位 = 可枚举/可比较的语义单元，是触发器和调度的锚点。**

#### 行业模板预置槽位（连锁型 v1 清单）

| 槽位 | 类型 | 示例 | 用途（被谁消费） |
|---|---|---|---|
| 设备类型 | 枚举 | 打印机/收银机/监控/点餐屏/秤/其他 | 分派技能匹配、统计 |
| 设备型号 | 文本 | 佳博 GP-C802V | 配件准备、相似案例检索 |
| 资产编号 | 文本 | GB01198 | 台账关联、保修判断 |
| 故障现象 | 短文本 | 红灯常亮不出单 | 相似案例、知识沉淀聚类 |
| 错误码 | 文本 | E-03 | 知识库精确命中 |
| 已尝试步骤 | 列表 | 重启/换纸 | 工程师上门前判断 |
| 期望上门时间 | 时间窗 | 今天 13:00 前 | 排程 |
| **是否投诉** | 布尔 | "我要投诉" | 触发器（§3） |
| **紧急度信号** | 枚举 | 停业/影响经营/局部/无 | 优先级建议输入 |
| 情绪 | 枚举 | 平和/着急/愤怒 | 人工服务台提示、回访策略 |
| 反复故障 | 布尔 | "上次也坏这里" | 升级处理、质量分析 |
| 保修状态 | 枚举 | 在保/过保/未知 | 结算（P1） |

品牌型增补：产品序列号、购买渠道、安装环境；品牌型槽位（尤其涉投诉/安全）**默认全部经确认卡人工确认后生效**。

#### 租户扩展槽位（解决"每家公司字段要求不同"）

租户管理员声明式配置：`槽位名 + 类型（枚举/文本/数值/布尔）+ 抽取示例 3 条`。AI 提炼时纳入 prompt；上线校准需提供 20–50 条标注样本（开通服务包内容）。租户槽位上限 20 个（防规则爆炸，见 §5）。

#### 槽位运行规则

- 每个槽位带**置信度**与**来源**（用户原话引用），确认卡上可点开溯源
- 抽取失败/低置信：**不阻塞流转**，槽位标"待补"，工程师端开单即带待补提示
- 槽位值修改全量留痕（谁/何时/原值），用于触发器审计

### 1.3 L3 自由叙事（AI 整理，不参与逻辑）

完整描述、照片、关联对话原文与 AI 摘要、处理时间线的叙事化呈现。渲染模板（现象/环境/已做/求助）由 AI 生成，**只服务人读**，任何自动化逻辑不得引用 L3 内容做判断（防止不可解释）。

### 1.4 表单的替代品：提炼确认卡

"填表"变"校对"：AI 提炼 L2 → 生成确认卡（每字段可编辑、置信度可视、原话可溯源）→ 用户/调度确认 = 提交。录入成本从"构思+填写"降为"核对"。三个触发口（AI 建议转单 / 用户直接报修 / 会话中生成）与 PRD §2.3 一致，**唯一变化：字段集合从固定表单变为 L1+当前已提炼槽位+待补标记**。

## 2. 触发引擎：双通道架构

**原则：LLM 负责"识别"，规则引擎负责"执行"，协同卡负责"低置信兜底"。自动执行的动作永远有确定性依据链。**

### 2.1 通道 A：事件规则引擎（确定性，不用 LLM）

条件类型：时间（SLA 超时/24h 未确认/入池 25 分钟）、状态变更、数值（负载/计数）。
预置规则（P0）：入池超 25 分钟提醒调度；接单超 10min 短信补发、20min 进兜底队列；结单 24h 自动完成；挂起超 48h 提醒。
P1 开放租户自定义：**条件 = 槽位/L1 字段 + 比较符 + 值** 的可视化配置器（下拉选择，非自然语言；AI 可辅助把口语转规则草稿，人确认后生效）。

### 2.2 通道 B：AI 意图分类器（语义识别）

- 任务形态：**受控分类/抽取**（输出限定在预定义槽位与受控词表），不是自由生成——这是可靠性的基础，当前模型受控分类准确率 95%+
- 与填单共用一次推理（成本控制），输出：槽位值 + 置信度 + 原话引用
- 分类边界维护：租户上线校准样本集；运行期人的"确认/纠正"持续回流（协同卡的负样本机制）

### 2.3 置信度分级处置（触发器可靠性的核心表）

| 判定置信 | 处置 | 例子（投诉判定） |
|---|---|---|
| ≥ 0.90 | **自动执行**规则动作，事后留痕可回滚 | 投诉=0.93 → 自动强制优先级≥高 + 直派调度岗 + 通知主管 |
| 0.70 – 0.90 | **生成协同卡**，人一键确认后执行 | 投诉=0.78 → 卡片"疑似投诉，建议直派+通知主管【确认执行】" |
| < 0.70 | 不触发，仅作为槽位参考值展示 | 投诉=0.55 → 现象里保留原话，不动作 |

阈值（0.90 / 0.70）为初始值，按租户可调（0.85–0.95 / 0.6–0.8），上线后按误触发率校准。**所有自动执行动作写审计日志：判定值、置信度、规则 ID、执行人（agent）、可回滚标记。**

### 2.4 全链路示例：投诉直派（用户原始问题）

```
用户："机器坏了三天没人管，我要投诉！"
① LLM 一次推理：投诉=true(0.93) 紧急度=影响经营(0.88) 情绪=愤怒(0.91)
② L2 槽位写入（含原话引用）
③ 规则引擎：投诉=true AND 置信≥0.90
   → 动作：优先级←高（覆盖 AI 建议值）+ 路由：人工服务台直派调度岗（跳过 AI 继续对话）
   → 通知：调度员（加急）+ 主管
④ 提炼确认卡同时生成：投诉标记高亮，用户可见"已按投诉处理"（透明度）
⑤ 若置信 0.78：③ 不自动执行 → 协同卡给调度员，确认后同 ③ 动作
```

## 3. SLA：纯策略层（零 LLM 依赖）

```
时限矩阵 = f(优先级 L1, 设备关键度 槽位, 网点等级 台账)
计时事件 = L1 时间戳（创建/分派/接单/签到/结单）
```

- 矩阵示例：紧急=响应30min/解决4h；高=30min/8h；中=2h/24h；低=4h/72h（工作时间内计时，P0 全时段，节假日日历 P1）
- 超时动作走通道 A（确定性）：提醒 → 升级通知 → 电话外呼（P1），全链可审计
- LLM 唯一参与：优先级建议（输入 L2 槽位，输出建议值+理由）→ 最终值是 L1 字段，人可改——**SLA 永远不依赖模型可靠性**

## 4. Agent 分级框架（按决策自主度，非按业务）

| 级别 | 定义 | 例子 | 人的介入方式 |
|---|---|---|---|
| L0 通知型 | 纯观察播报 | 早报、状态播报、知识引用统计 | 无 |
| L1 建议型 | 人批准才动 | 自动派单建议、中置信知识入库、回访差评转工单 | **协同卡确认**（=触发器低置信兜底同一机制，复用） |
| L2 半自主 | 白名单内自动+事后留痕可回滚 | 高置信知识入库、低优先级自动分派（P1）、催办提醒 | 事后审计 + 回滚（30 天） |
| L3 自主 | 异常时才找人 | 自动调度、质检巡检（P2） | 异常升级协同卡 |

规则：每个 agent 在注册时声明级别与白名单边界；L2 以上强制留痕可回滚；级别与白名单租户管理员可下调不可上调（安全默认）。

现有 agent 映射（P0/P1）：知识沉淀=L1+L2 混合（按质量门置信分流）、自动派单=P1 起 L1（P1 白名单内低优先级可 L2）、SLA 升级=L1（预警不自动改派，P1 可授权）、满意度回访=L1、工单工作台=人操作的聚合入口（非 agent）。

## 5. 风险与对策（诚实清单）

| 风险 | 对策 |
|---|---|
| 槽位抽取歧义（"佳博那台"） | 不阻塞流转 + 待补提示 + 相似案例反哺 + 确认卡溯源 |
| 规则爆炸/冲突 | 租户槽位上限 20、触发器上限 30；P1 冲突检测与优先级 |
| 分类边界漂移 | 上线校准样本 + 人的纠正回流 + 月度误触发率报告 |
| 自动执行误判 | 置信阈值 + 白名单 + 全量留痕 + 回滚；首月建议阈值调高（0.95）观察 |
| 成本 | 填单与分类共用一次推理；高频 FAQ 缓存；按租户计量 |
| 用户不接受"被 AI 理解" | 确认卡透明展示提取值与原话引用；一切可改 |
