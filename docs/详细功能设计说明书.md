## 1. 全局机制（底座）

### 1.1 多租户与租户档案

| 机制 | 规则 |
|---|---|
| 隔离 | 数据层强制隔离（行级 RLS，服务端拦截跨租户访问）；文件与向量索引按租户分 namespace |
| 档案 | 连锁型 / 品牌型两套默认配置（见 PRD §5 差异表），租户创建时选定，可申请切换（管理员操作，数据映射由实施 checklist 保证） |
| 品牌化 | 用户端 H5 的 LOGO/名称/主题色（蓝/绿两套预设，自定义 P2）；管理端与工程师端固定平台品牌 |
| 组织树 | 租户 → 区域（连锁=城区，品牌=大区）→ 网点/客户；调度权限可按区域裁剪 |

### 1.2 角色权限矩阵（P0）

| 能力 | 租户管理员 | 管理者 | 调度员 | 知识管理员 | 工程师/服务商 | 用户 |
|---|---|---|---|---|---|---|
| AI 工作台问询 | ✓ | ✓ | ✓ | ✓ | — | — |
| 协同卡处理 | ✓ | 审批类 | ✓ | 知识类 | — | — |
| 派单/改派 | ✓ | ✗ | ✓ | ✗ | — | — |
| 人工会话接入 | ✓ | ✗ | ✓ | ✗ | — | — |
| 知识库管理 | ✓ | 只读 | 只读 | ✓ | 只读本服务商 | — |
| 数据看板 | ✓ 全租户 | ✓ 全租户 | ✓ 本区域 | ✗ | 本人统计 | — |
| 服务商结算（P1） | ✓ | 只读 | 只读 | ✗ | 本服务商对账单 | — |

### 1.3 身份体系

- **连锁型用户（店员）**：管理员批量导入手机号 → 首次验证码登录绑定身份（姓名/网点）；网点变更由管理员迁移
- **品牌型用户（消费者）**：手机号验证码 / 微信授权，首次登录创建轻量客户档案（姓名+地址+设备序列号可选填）
- **工程师**：手机验证码零注册 → 首次接单前补全（实名/所属服务商/技能）→ 调度员审核入池；服务商成员仅见本服务商工单
- **管理端角色**：账号密码 + 手机验证码双因子（P0 单因子，双因子 P1）

### 1.4 通知总线（全端统一）

**通道**：小程序订阅消息 / 微信服务号模板 / 短信 / 飞书·钉钉应用消息（P0 一个生态）/ 电话外呼（P1）。

**事件矩阵**（P0）：

| 事件 | 接收人 | 降级链 | 送达状态 |
|---|---|---|---|
| 新工单待分派 | 调度员组 | 生态消息→短信 | 送达/未送达 |
| 工单分派 | 工程师 | 订阅消息→服务号→短信 | 送达/已点击/降级中 |
| 接单/改派 | 用户+调度 | 用户端推送→服务号 | 送达 |
| 上门前 1h 提醒 | 用户+工程师 | 订阅消息/服务号 | 送达 |
| 结单待确认 | 用户 | 推送→服务号→短信（24h 未确认自动完成并告知） | 送达 |
| 转人工排队 | 当班调度 | 生态加急→短信（3min 无人接入→电话外呼 P1） | 送达/已接入 |
| 送达失败 | 调度员 | 兜底队列（工作台强提醒） | — |

**规则**：全量送达留痕（通道/时间/状态）入通知记录表；订阅消息额度池监控（低于 20% 告警管理员）；同一事件对同一人 5 分钟内去重。

### 1.5 LLM 网关

| 机制 | 规则 |
|---|---|
| 能力路由 | 对话问答 / RAG / 填单 / 摘要 / 相似案例 / 指令解析，统一网关接口，模型按能力配置 |
| 供应商 | 主备双供应商，主故障 5 分钟自动切换，切换记录运营公告 |
| 计量 | 按租户 × 能力 × 日计量 token 与调用数；超出套餐阈值降级提示（不熔断） |
| 脱敏 | 联网搜索前置过滤器：网点名/资产号/手机号/单据号替换占位符；该规则在架构层强制，不依赖提示词 |
| 降级 | LLM 不可用：用户端暂停 AI 回答（提示+转人工入口常亮）、指令模式禁用；工单流转/通知/人工会话不受影响 |
| 缓存 | 高频 FAQ 命中缓存（知识条目+问题向量相似度>0.95），缓存回答标注"常见问题" |

### 1.6 知识库引擎（RAG）与质量门

**来源与优先级**：租户自建文档 > 飞书同步 > 历史工单沉淀 > 联网兜底（标注"联网参考"，不作权威依据）。

**检索规则**：向量 + 关键词混合检索，Top3 入上下文；**受众分域（P0）**：知识条目带受众标签（用户可见 / 仅工程师 / 仅内部），检索按提问者身份过滤——维修手册、内部 SOP、错误码表仅工程师可检索，基础操作文档用户端可见；引用必须回溯到源段落；**回答置信度 < 0.72**（连锁型）时 AI 不硬答，主动建议转人工/建单；品牌型阈值更高（0.80 起，联调定）。

**同步**：飞书知识空间/目录级授权，增量同步默认 2 小时；删除文档自动从索引移除（已发回答不追溯）。

**质量门（沉淀闭环）**：

| 置信度 | 动作 | 规则 |
|---|---|---|
| ≥0.85 | 自动入库 | 留痕可回滚（30 天内）；品牌型默认全部转人审 |
| 0.60–0.85 | 生成草稿 → 人审队列 | 知识管理员审核，通过即生效 |
| <0.60 | 不沉淀 | 仅计数 |

置信度输入：结单摘要完整度、与现有知识相似度（去重）、该工程师历史采纳率。回滚需填原因，回滚的知识 30 天内不再自动入库。

## 2. 用户端（售后豆包，H5 租户品牌化）

### 2.1 会话管理

- 布局：左栏会话清单（桌面）/ 列表首页（移动）；新会话按钮常驻
- 标题：首轮问题 AI 生成 ≤20 字，用户不可改（降低维护成本）
- 列表：按最后活跃倒序；含工单的会话带工单角标；分今天/昨天/更早（用户端会话量小，保留时间分组）
- 归档：90 天未活跃转归档（"查看更多"入口）；会话本身永久保留只读
- 追问：在历史会话中继续提问，上下文延续；已归档会话追问 = 开新会话并引用摘要

### 2.2 问答流程（每轮）

```
用户输入(文本/图片) → 意图预判(咨询/报修/进度查询)
→ 咨询类：知识库检索 → 命中→回答+引用来源+追问建议
                    → 未命中→ 联网搜索(脱敏后)+标注"联网参考"
→ 报修类：先给自检步骤(检索知识库)→ 无效则建议转工单(填单卡)
→ 进度类：查工单表 → 返回工单卡+状态
```

- 每轮回答必带来源标签（知识库 n 条 / 联网 / 实时数据）；无依据时明说"没找到依据，建议转工单"
- 图片 P0 仅存储+人工查看；错误码/铭牌识别 P1
- 逃生门常驻：转人工（→管理端人工服务台，交接摘要自动附带）/ 直接报修（跳过对话直接填单卡，仍带会话上下文预填）

### 2.3 AI 填单

> 字段模型依据《工单模型与触发引擎设计.md》§1：无固定录入表单，字段集合 = **L1 系统字段 + L2 已提炼语义槽位（带置信度）+ 待补标记**；"填表"交互 = AI 提炼确认卡（校对式确认）。

| 规则 | 说明 |
|---|---|
| 触发 | ① AI 判定无法远程解决主动建议；② 用户点"直接报修"；③ 会话中点"生成工单" |
| 预填字段 | 网点（身份带出）、设备（台账匹配/用户输入）、现象（对话归纳）、已尝试步骤、图片（会话照片带入）、优先级（AI 建议+理由）、期望时间 |
| 确认 | 每字段可编辑；必填校验：现象≥10 字或含图；品牌型加联系方式+地址 |
| 提交 | 生成工单进入待分派；会话内插入工单卡；后续状态变更以消息形式回流会话 |

### 2.4 工单跟踪

- 状态步骤条：提交→分派→上门→完成；每步时间戳
- 工程师信息脱敏展示（姓名+电话中间四位）
- 待确认态：用户确认 / 驳回（必填原因）；24h 无操作自动完成（提前告知）
- 所有状态变更按通知矩阵推送（H5 站内 + 服务号/短信可选）

## 3. 工程师端（微信小程序为主 + 一个生态端）

### 3.1 小程序页面与流程状态

```
工单列表(待接单/进行中/已完成) → 工单详情 → 接单 → 上门签到 → 处理记录 → 提交结单
消息中心(送达留痕) / 我的(资料、技能、订阅、知识贡献)
```

### 3.2 关键规则

| 环节 | 规则 |
|---|---|
| 接单 | 分派通知降级链送达；**10 分钟未接单→短信补发；20 分钟→进调度兜底队列并建议改派**；拒单必填原因（原因进 agent 负样本） |
| 负载 | 在办/上限（默认上限 4，服务商管理员可调 1–6）；满载不再派单 |
| 签到 | 定位打卡，与网点地址偏差 >500m 记录标记（不阻断）；签到时间=服务计时起点 |
| 处理记录 | 文字+照片可多次追加，实时同步调度侧时间线 |
| 结单 | 摘要 AI 草稿（可改）必填；配件记录（P0 仅记录）；照片≥1 张（租户可配置≥2）；提交→用户待确认 |
| 相似案例 | 打开工单即带：知识库相似文档 + 历史相似工单（复用 RAG，标注来源） |
| 消息中心 | 每条通知展示降级链路径与送达状态；订阅消息额度一键补充（引导授权） |
| 零注册 | 验证码即登录；首次接单补资料+调度审核入池 |

### 3.2.1 工程师 AI 问答（P0：三层递进，共用 RAG 引擎）

| 层 | 形态 | 规则 |
|---|---|---|
| ① 被动推 | 开单即带相似案例 | 已有（§3.2） |
| ② 工单内问答（主形态） | 工单详情内"问 AI"输入框 | 默认携带工单上下文（设备型号/故障/已做步骤）；回答带引用；**问答以 AI 身份同步进工单协同区（三方可见、透明）**；结单时问答自动成为沉淀素材，工程师点"有帮助"的优先入库 |
| ③ 全局"问一问" | 首页单页问答 | **不做会话列表**，仅保留最近查询；检索范围=工程师域知识+历史工单；回答标注"仅工程师域" |

覆盖场景：维修手册/错误码查询、不熟悉型号的步骤、配件兼容性、保内判断、新人自学。语音提问 P1（现场双手占用）。

### 3.3 生态端（飞书或钉钉其一，P0）

- 形态：ISV 应用消息卡片 = 通知 + 轻操作（接单 / 改状态 / 查工单，跳 H5 详情）
- 定位：内部员工与深度生态客户的可靠通知通道；完整操作引导至小程序

## 4. 管理端（Web）

### 4.1 AI 工作台（首屏）

**→ 详见《AI工作台-功能设计.md》**：四类流合一（Agent 协同 / 人工会话 / AI 问询 / 工单指令）、左栏四区收敛规则、中栏四态状态机、右栏四态面板、协同卡与指令确认卡两大原子组件。

### 4.2 运营概览（原工作台）

| 指标 | 口径 |
|---|---|
| 待分派 | 当前状态=待分派的工单数；"即将超时"= 进入池超 25 分钟（SLA 30min） |
| 进行中 | 状态∈{待接单,已接单,处理中,挂起,待确认} |
| AI 拦截率 | （未生成工单且未转人工的会话）/（总会话），会话=用户发起且≥1轮问答；实时（当日）+T+1（历史） |
| 分派首响 | 工单创建→首次分派完成，工作时间内计算 |
| 通知兜底队列 | 降级链走完未确认的工单，操作：重发/电话/改派 |

### 4.3 派单台

- 待分派池排序：超时风险 > 优先级 > 创建时间；卡片含 AI 分派建议（进入池 5 分钟未分派自动生成或手动刷新）
- 资源池列表：状态（空闲/忙碌/离线=今日无上线）、在办/上限、技能标签、服务区域、评分
- 分派动作：选中工单+工程师 → 确认（展示降级链提示）→ 触发通知；改派需填原因并保留原时间线
- 代客建单：电话渠道由调度录入，AI 对口语描述做语义预填（P1 语音转写）
- 地图视图 P1

### 4.4 工单管理

- 列表：筛选（状态/优先级/类型/来源/网点）+ 搜索 + CSV 导出（当前筛选结果）
- 详情抽屉：基本信息、关联会话入口（对话原文+AI 摘要）、时间线（全事件留痕）、**工单协同区（§4.4.1）**、操作（分派/改派/备注/关闭需原因）
- 状态机与字段遵循 PRD §8/§9；SLA 字段 P0 预留、引擎 P1

#### 4.4.1 工单协同区（互动沟通，替代电话协同）

**定位**：工单 = 结构化数据 + 沟通流（类 issue comments）。建单后所有内外部沟通在工单内完成。

| 维度 | 规则 |
|---|---|
| 参与方 | 用户（用户端工单卡内发言）、工程师（小程序工单详情发言）、调度员/管理者（管理端工单详情发言）；**AI 为第四参与方**：自动应答事实类问题（配件库存/保修状态/工程师位置/进度），标注"AI"身份 |
| 消息类型 | 三方消息 + 系统事件（状态变更/签到/结单自动同步进流，构成"活的时间线"）+ AI 自动应答 |
| 可见性 | 默认全员可见（同一工单下的公开协同）；"仅内部"备注（调度↔工程师，用户不可见）P1 上线，P0 全公开 |
| 通知联动 | 新消息按角色走通知总线：用户→服务号/推送；工程师→订阅消息；调度→工作台红点；@提及 P1 |
| 阶段分工 | 会话管"建单前"（咨询/拦截/转人工），协同区管"建单后"；结单后协同区随工单归档（90 天只读） |
| 图片 | 三方均可发图（现场照片/单据），进入工单附件（L3 叙事的一部分） |
| 审计 | 协同消息全量留痕、不可删除（可撤回自己 2 分钟内的消息） |

### 4.5 资源池

- 工程师：信息/技能标签/服务区域/在办上限/启停用/认证记录；服务商成员仅本服务商工单可见（服务端过滤）
- 服务商：企业信息、成员管理、覆盖区域、质量记录（完成量/平均时长/驳回率/评分，月度滚动）
- 准入：新工程师首单前调度审核；服务商准入评估走 AI 问询（评估模板）

### 4.6 网点与设备台账（连锁型重点）

- 网点：编号/名称/区域/地址/负责人/设备数/在保数/近30天工单数；Excel 批量导入（模板校验：必填列+区域字典）
- 设备：挂靠网点、名称/型号/资产号/保修到期（到期前 30 天列表提醒）；工单调用设备档案自动填入
- 品牌型：网点概念替换为客户+安装地址，设备=序列号登记（用户端可自助登记）

### 4.7 知识库管理

- 文档列表：来源标签（自建/飞书同步/工单沉淀）+ 被引用次数 + 同步状态
- 审核队列：质量门草稿（通过/暂缓/回滚，见 §1.6）
- 飞书同步任务：知识空间选择、增量周期、失败原因展示、手动重试
- AI 行为配置：联网开关、置信度阈值（0.5–0.95 滑条）、免责话术（品牌型强制开）

### 4.8 数据看板（T+1）

拦截率趋势（北极星）、工单量与来源结构、SLA 达成、网点工单 TOP、服务商质量排名、单工单成本（人工+上门成本/工单量，环比）；导出 P1。

### 4.9 系统设置

AI 行为（§1.6）、通知模板与降级链顺序、角色权限、租户档案项、渠道接入（企微/飞书工作台入口配置）、操作审计日志（管理端全量操作留痕，管理员可查）。

## 5. 端到端主流程（飞轮闭环时序）

```
① 用户提问 → ② AI 检索知识库回答(附来源)
  ├─ 解决 → 会话结束(计数拦截率) 
  └─ 未解决 → ③ AI 填单卡 → 用户确认 → 工单[待分派]
→ ④ 调度(AI 工作台协同卡/指令/派单台) → 工程师接单(通知降级链)
→ ⑤ 上门签到 → 处理记录 → ⑥ 结单(AI 摘要草稿)
→ ⑦ 用户确认(24h 自动) → ⑧ 质量门评估 → 入库/草稿/不沉淀
→ ⑨ 知识库变厚 → 拦截率↑ → 人工工单↓
```

每个环节的异常出口：② 未命中→联网/坦诚告知；④ 超时→兜底队列；接单超时→改派；⑥ 驳回→回处理中（必填原因）；⑧ 污染防护→人审+回滚。

## 7. 全局非功能与异常

- 性能基线（PRD §11 待确认）：对话首 token 3s / API P95 500ms / 10 万工单每月
- 可用性：99.5%；通知总线独立部署、失败可重放；LLM 主备 5 分钟切换
- 安全：租户隔离、PII 加密与脱敏展示、出网脱敏（架构层）、操作审计、日志脱敏
- 并发：协同卡乐观锁；人工会话一人服务锁；断线按 sequence 增量同步
